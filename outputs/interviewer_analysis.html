2SkillOpt 单步训练管线理解后续图表的前提

每一步训练 = 让目标模型带着当前技能对样本面试做评分 → 根据失败/成功轨迹反思生成技能修改 → 合并 → 用「学习率（edit budget）」控制修改量 → 打补丁 → 在验证集上严格评测，只有严格超过当前最优才接受。

① ROLLOUT目标模型用当前技能评分样本
→
② REFLECT分析失败/成功轨迹，生成 edits
→
③ AGGREGATE并行合并多个反思结果
→
④ SELECTedit_budget 控量（学习率）
→
⑤ UPDATE以 patch 方式改技能
→
⑥ EVALUATEgate=hard，严格 accept/reject

每个 epoch 结束后（仅实验 B）：slow update 跨 epoch 对比同一样本表现，产出「评分守则」注入技能；meta skill 把优化器记忆写入下一轮反思上下文。

3论点一：SkillOpt 几分钟级训练 ≈ 人类 + AI 工具半天～一天的成果interviewer_blank · 34 条保安样本

对照组：data/interviewer_data/SKILL_template.md，是「人类专家 + AI 工具」反复打磨约半天～一天得到的保安岗位最优评分细则。实验组：SkillOpt 从同一岗位的 34 条真实样本出发，自动训练约 27 分钟。两者产出的评分细则在评分维度、顺序、合格标准上惊人一致（8/8）。

结论：只需约 27 分钟，SkillOpt 从「随机看心情」的空白技能出发，自动收敛到与精英人工打磨结果高度同构的评分细则 —— 无论判断维度还是评分标准。人工成本从半天～一天压缩到半小时内，且可复现、可迁移。

4论点二：超少样本（3 条）+ 慢更新，同样得到优质技能，还学到了细则之外的评分守则interviewer_blank2 · 3 条保洁样本

同样的空白起点，只喂 3 条真实保洁面试样本（2 条「不通過」+ 1 条「通过」）。通过调优训练参数（10 epochs、batch=3、min_edit_budget=1）并开启 slow update / meta skill，selection 从 0 分起步并最终达到 0.667；同时技能沉淀出 15 条评分细则之外的「评分守则」。

4.2 每步技能的「长度」与「内容」演化：修修补补 → 沉淀守则

图 C：每步技能字符数（出自 history.json 的 skill_len）。灰色 = 未接受的候选替换；橙色柱 = 该步有 slow update 守则注入；绿色 = 最终 best skill（3165 字符，含 SLOW_UPDATE 守则区）。

  • 第 1 步（660→908）：从 1 条成功样本轨迹的反思考评里凝练出第一批实质细则 —— 长度只小幅增长，避免大改大动
  • 第 2 步（→1691）：先补「保洁/清洁经验」的间接相关判定（0.5 档），接受后 selection 达 0.433 —— 内容向数据里的真实岗位（清潔員）靠拢
  • 第 3 步被拒：候选（1796）把细则改坏（selection 掉到 0.1），被 gate 拒绝，技能回滚 —— 内容变化被「验证后接受」保护
  • 第 4-10 步：每轮 slow update 把跨轮分析出的守则以 patch 方式写入技能（831→1475 字符），技能从「纯评分表」长成「评分表 + 评分守则」—— 最终 best skill 比初始技能长约 4.8 倍，其中约 47% 字符是评分细则之外的行为守则（SLOW_UPDATE 区 1477 字符 / 3165 字符）

  • 学习率控制：每轮 reflection 产出的 edit 数在 SELECT 阶段被 edit_budget=2 截断；3 样本下实际每步只合并 1-2 个 edit —— 技能变化小、可回滚，10 轮从未崩坏超过一步
  • 严格验收：gate=hard，候选必须先跑 selection 评测，只有严格大于当前最优才 accept；低分候选（0.1）和持平候选（0.4333）一律 reject —— 4 次 REJECT 恰好守住了 0.433 的平台期，防止低质量 edit 污染技能（logs_detail.txt 中每步都有明确的 ACCEPT / REJECT 记录与得分）

4.4 slow update：跨 epoch 逐样本对比，发现「分数之外」的规律

slow update 每轮重新采样训练样本（seed 递增），把同一候选人在上一轮 vs 本轮的表现做逐项对比（回归 / 改进 / 顽固失败 / 稳定成功），再决定是否把规律性结论注入技能。9 轮跨 epoch 分析中 6 轮产出了守则注入：

  • meta skill 同步记忆：每轮把优化器经验写入记忆（758～2661 字符），让后续反思「站在上一轮的思考上」，不重复踩坑

4.5 学到的不只是分数表：细则之外的「评分守则」（SLOW_UPDATE 区）

最终 best_skill 在 8 条细则之外多出约 1400 字符的 SLOW_UPDATE 守则区（15 条编号规则），可归为四类 —— 这些内容评分细则表本身永远写不出来：

① 输出铁律 —— 解决「拿不到分」的根因（规则 1-4）

必须输出一行 <score>X.X</score>，第一个字符是 <、最后一个字符是 >；禁止任何前后缀文字；宁可给估算分也绝不交付空白回复 —— 直接针对基线 0 分（3 条全错）的原因：模型没有稳定输出可解析的分数标签。

② 证据型评分校准锚点 —— 把「差不多」变成「可判定」（规则 5-13）

只依据明确证据打分；保洁/清洁/临时顶班 = 间接相关 0.5，保安/物管直接经验 = 1；「识少少」「可以学」= 0.5，能流畅读写繁体字才 = 1；笼统说「服从安排」= 0.5，给出「以前长期做清洁、收潲水都做过」这类具体佐证才 = 1。还专门针对数据特殊性写了第 13 条：面试官介绍岗位为洗手间清洁/收潲水时，不要质疑与「保安员」不一致，照常评分 —— 这是 3 条保洁样本数据里蕴含的真实规律。

③ 防漂移校准 —— 同一证据只能得同一分（规则 14）

只看证据强度，不看整体印象、转录长度或回答顺序；同一录音在两个版本间出现 0.5 漂移时以「无证据=0 / 含糊=0.5 / 明确=1」的锚点为准 —— 回应了 slow update 连续三轮观察到的「回归/漂移」。

④ 收尾自检 —— 稳定性的最后一道闸（规则 15）

发送前 1 秒自检：是否以 <score> 开头、以 </score> 结尾、只有这一行？不满足就改写再发。保证评分输出格式的长期稳定。

🧠

结论：slow update 的跨 epoch 对比不只是「调分数」，而是从样本的反复表现里归纳出新的行为守则（输出格式、证据锚点、防漂移、自检）。3 条样本不足以让评分表完美，但足以让「怎么评分」这件事变得稳定和可解释 —— 这是超少样本场景下最有价值的收获。

4.6 泛化到测试集：0.667 → 0.767（+0.100）

图 E：best skill 在 test 上的表现。基线（空白技能）test=0.6667 → best skill（slow_update_epoch_10）test=0.7667，含 0.3 中间区加权分（2.3/3 = 1.0 + 1.0 + 0.3）。
